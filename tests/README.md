# Проверка поведения infostyle

Набор из 20 независимых редакторских задач находится в [cases.json](cases.json). Это проверки поведения модели, а не поиск нужных слов в инструкции.

Фактические ответы и оценки первого прогона: [14 сентября 2026 года](runs/2026-09-14.json). Пройдены 20 из 20 задач в трёх отдельных сессиях агента, пакетами по 7, 7 и 6 запросов. Проверялась инструкция в среде Codex; Claude Code отдельно не запускался. Ограничения и контрольные суммы проверенных файлов записаны в отчёте.

## Как проводить

1. Зафиксировать версию скилла, модель и дату.
2. Передать исполнителю только папку скилла и поле `prompt` выбранной задачи. Критерии оценки и предыдущие ответы исполнителю не показывать.
3. Сохранить фактический ответ. Оценить его отдельно по `criteria`, сверяя с исходным заданием.
4. Зафиксировать результат по каждой задаче: прошла, не прошла, не проверена; при ошибке — конкретное нарушенное условие.
5. После исправления повторить затронутые задачи. Повторная проверка всех случаев нужна, если правка меняет общее поведение.

Несколько коротких задач можно дать исполнителю одним пакетом, явно разделив их. Такой пакет — предварительная проверка: задачи в нём разделяют контекст. Для оценки устойчивости лучше отдельная новая сессия на каждый случай и несколько повторений.

## Что считать успехом

Сохранены существенные факты и ограничения, выполнен запрос пользователя, не потеряны термины, понятность и уместный голос. Критерии проверяют смысл и границы задачи, а не единственную «идеальную» формулировку.

Не оценивайте качество только по сокращению количества знаков, отсутствию стоп-слов или числу редакторских проходов. Допустимый результат — исходный текст без правок.

Особое внимание:
- неподтверждённым числам, обещаниям и причинам;
- потере условий и степени уверенности;
- нежелательной полной переработке;
- стиранию авторского голоса;
- изменению поведения программы при редактуре надписи.

## Сравнение версий

Для измерения эффекта сравнивайте одну и ту же модель с одинаковыми настройками и заданиями: со скиллом до изменения, после изменения и при необходимости без него. Порядок ответов при оценке полезно скрыть.

Одиночный успешный прогон подтверждает только прохождение конкретных заданий. Он не доказывает улучшение всех текстов, рост конверсии или отсутствие будущих ошибок.

## Структурная проверка

Отдельно проверьте YAML-заголовок, разрешение относительных ссылок и наличие всех файлов `references/` в копируемой папке скилла. Эти проверки не заменяют редакторские задачи.
